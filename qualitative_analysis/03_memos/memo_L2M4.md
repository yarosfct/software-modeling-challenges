TITLE: Tools motivate through code and constrain mistakes, but collaboration is still missing
DATE: 09/04/2026
INTERVIEW / SOURCE: Lecturer interview 2
RELATED RQ(s): 
RELATED CODES: code generation motivates modelling; tool-supported error prevention; tooling prepares industry adaptation; video onboarding plus exploration; installation friction; missing real-time collaboration
CATEGORY / THEME: Tooling / desired supports

1. What is happening here?
The lecturer values modelling tools because they motivate students, prevent some errors, and prepare students for complex tools they may later encounter in industry. At the same time, the lecturer says current tools still lack useful real-time collaboration and communication support.

2. Why is this analytically important?
This shows that the tool is seen as part of the pedagogy, not just a neutral medium. Tool choice affects motivation, correctness, and future professional transfer.

3. What seems to be the underlying issue?
Students appear more motivated when modelling visibly connects to code. But the lecturer also wants tools that support project coordination, not only local model editing.

4. What evidence supports this?
- "one that can generate code, because that motivates them"
- "they prevent some syntax errors and some classic mistakes"
- "they can adapt more easily"
- "First, I provide short videos... then I ask them to explore the tool"
- "What I miss most is real-time collaboration and communication features"

5. What tensions / contradictions appear?
The tool is valued for being complete and protective, yet some of the broader collaborative work still has to happen in separate platforms.

7. Implications
An educational modelling tool may need to combine syntax support, motivational links to implementation, and lightweight collaboration features rather than prioritizing only diagram editing.

8. Follow-up questions
