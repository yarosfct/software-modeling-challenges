TITLE: Semantic tools help, but family fragmentation remains unsolved
DATE: 08/06/2026
INTERVIEW / SOURCE: Lecturer interview 4
RELATED RQ(s): 
RELATED CODES: PyStar enforces iStar semantics; lack of integrated teaching tools; no cross-family tool integration; tool funding as top priority; desired cross-paradigm integrated tool; semantic checking for iStar but not NFR
CATEGORY / THEME: Tooling

1. What is happening here?
The lecturer values PyStar because it enforces iStar semantics, but lacks integrated support across iStar, NFR refinements, SUSAF, and UML. Free tools are used, yet family-specific fragmentation persists. The lecturer's realistic improvement priority is a lightweight, validity-checking, cross-paradigm tool and would spend project funding on tools before almost anything else.

2. Why is this analytically important?
This interview separates drawing tools from method-specific, semantically aware tools. The teaching vision needs integration across paradigms, but the current ecosystem forces whiteboard compensation and tool switching.

3. What seems to be the underlying issue?
Each modelling family has partial tool support, but teaching requirements engineering as a pipeline exposes the absence of a single environment for linked perspectives, rationale, and validation.

4. What evidence supports this?
- "if a student builds a model in PyStar, I know the model is semantically correct"
- "I do not have good integrated tools for what I want to teach"
- "integration across modelling language families does not exist"
- "If I had project funding... it would be for tools"
- "a lightweight tool with validity checks that supports some integration across different paradigms"
- "I have that for iStar, but not for NFR refinements"

5. What tensions / contradictions appear?
The lecturer compensates through discussion and whiteboards, which work pedagogically but do not solve semantic checking for all families or reduce tool friction for students.

6. How does this relate to other interviews or literature?
Compared with lecturer interview 3, who had executable UML in USE as a distinctive strength, L4 has semantic checking for iStar but not execution or integrated NFR support. Compared with student interview 3, who benefited from BPMN-specific Bizagi for beginners, L4 also values family-specific tools but needs cross-family linkage rather than only specialisation.

7. Implications
Tool design for modelling education should target lightweight integration across families, semantic validation, rationale capture, and collaboration, not just better drawing.

8. Follow-up questions
What minimum integration would help most: cross-model traceability, shared rationale, or unified feedback workflows? Could LLM-based semantic feedback partially substitute for missing tool integration?
