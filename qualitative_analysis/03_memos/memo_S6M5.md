TITLE: Tool integration problems mirror conceptual integration problems
DATE: 09/06/2026
INTERVIEW / SOURCE: Student interview 6 (reconstructed)
RELATED RQ(s): RQ2, RQ3
RELATED CODES: semantic checks support iStar correctness; tool-switching without integration; partial slides insufficient for NFR learning; desired AI semantic model-text comparison; continuous traceable example across model families
CATEGORY / THEME: Tool support and cross-family integration

1. What is happening here?
S6 values semantic checks in the iStar tool but experiences friction when UML is done in a separate drawing tool without integration. The desired improvement is a continuous traceable example or integrated support across model families.

2. Why is this analytically important?
The tool problem reflects the conceptual problem. Students struggle to preserve meaning between models, and the tools also fail to preserve links between them.

3. What seems to be the underlying issue?
The underlying issue is fragmented support. Each modelling family may have its own tool and examples, but students need help with the relationships between them.

4. What evidence supports this?
- "It prevented illegal dependencies"
- "UML was done in a standard drawing tool without integration"
- "Switching tools created friction"
- "one continuous example from goals to NFR decisions to UML, with trace links documented"

5. What tensions / contradictions appear?
Family-specific tools provide semantic correctness but can increase fragmentation. Integrated tools would help, but may be unavailable or too complex.

6. How does this relate to other interviews or literature?
L4 similarly wants a lightweight integrated tool that supports early and late requirements. S6 provides student evidence for why integration matters in learning.

7. Implications
Where integrated tools are unavailable, courses could use shared rationale tables or traceability matrices as lightweight connective tissue between tools.

8. Follow-up questions
Would a simple traceability table reduce the pain of switching tools, or do students need automated validation?
