# S4M1 — group work can kill modelling when code wins

- Case: S4
- Codes: S4-C02, S4-C09, S4-C11
- Turns: T007, T017, T021

## Idea
In a generic shop group project, teammates pushed Spring implementation while the student maintained the class diagram alone; dismissal as "paperwork" stopped refinement until the model no longer matched code. Modelling worked later when one person owned an interesting library design; early sharing in groups turned diagrams into arguments rather than improvements.

## Why it matters
Socio-technical conditions—ownership split, domain interest, group dynamics—can matter more than UML notation knowledge for whether modelling persists.
