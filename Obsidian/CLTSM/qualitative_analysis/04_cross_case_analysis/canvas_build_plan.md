# Canvas Build Plan

## Purpose

This file is the working protocol for building Obsidian canvases as grounded-theory analytic workspaces. The canvases are not presentation graphics. They are places to identify, compare, triangulate, refine, and integrate emerging concepts across the thesis evidence base.

Build one topic canvas at a time. Keep the visual structure simple and put the analytical density inside linked notes. Topic canvases should later connect into a broader theory canvas once several topic-level interpretations have been refined.

## Resume Note

This file is the source of truth for resuming the canvas-building workflow across machines or future Codex chats. If some canvases have already been built, do not restart the whole process. Open this file, find the first topic whose checklist is not complete, inspect the existing `.canvas` file and its linked notes, then continue from the next unchecked step.

When resuming with Codex, start by saying which topic canvas you want to continue, or ask Codex to inspect this build plan and the existing canvas files. Codex should then:

- read this build plan;
- check which topic canvases already exist;
- inspect the relevant canvas and linked notes before editing anything;
- continue the standard protocol from the next incomplete step;
- update the topic checklist in this file only after that step is actually done;
- preserve existing canvas work unless you explicitly ask for restructuring.

Use the topic checklists below as progress markers. A checked item should mean the file, note, attachment, or review step exists in the vault, not just that it was planned.

## Grounded-Theory Logic

- Open coding: use incidents from comparison files and memos to label challenges, strategies, conditions, supports, and consequences.
- Axial coding: relate categories through `conditions -> actions/interactions -> outcomes`.
- Selective/theoretical integration: connect topic-level interpretations to the core phenomenon and the developing account of socio-technical modelling judgement.
- Constant comparison: compare student and lecturer evidence, positive and negative cases, strong and weak instances, and different source types.
- Triangulation: compare comparison notes, memos, cross-case notes, negative cases, methodological cautions, and unresolved evidence checks before treating an interpretation as stable.

## Standard Canvas Template

Use this structure for every topic canvas:

```text
Topic Overview
     ->
Open Coding Evidence
     ->
Axial Coding Map
     ->
Triangulation / Negative Cases
     ->
Refined Interpretation
     ->
Links to Broader Theory
```

Each box should be a note. Attach comparison files, memo files, and negative-case files to the note where they are analytically useful. Avoid dense connection instructions; the canvas should show the basic analytic flow while the notes carry the detailed reasoning.

## Reusable Canvas Protocol

### Step 1: Create topic canvas shell

- [ ] Create the canvas file.
- [ ] Add the six standard notes from the template.
- [ ] Arrange the notes left to right or top to bottom in the standard order.
- [ ] Add only simple directional links between the six notes.

### Step 2: Add open-coding evidence groups

- [ ] Attach the topic comparison note.
- [ ] Attach the key memo files.
- [ ] In the Open Coding Evidence note, group incidents as challenges, strategies, conditions, supports, and consequences.
- [ ] Mark where evidence comes from students, lecturers, or both.

### Step 3: Add axial coding structure

- [ ] In the Axial Coding Map note, organise categories as `conditions -> actions/interactions -> outcomes`.
- [ ] Note mediating factors such as assessment structure, feedback access, tools, domain constraints, or prior modelling experience.
- [ ] Identify where the topic changes representational judgement, uncertainty, confidence, or revision.

### Step 4: Add triangulation notes

- [ ] Attach negative-case files where relevant.
- [ ] Compare student evidence against lecturer evidence.
- [ ] Compare topic comparison files against memo-level evidence.
- [ ] Mark contradictions, missing evidence, or methodological cautions.
- [ ] Record open checks instead of forcing premature closure.

### Step 5: Add refined interpretation

- [ ] Write a short interpretation that states the emerging pattern.
- [ ] Make the interpretation conditional rather than universal.
- [ ] Include boundaries: where the pattern is strong, weak, contradicted, or under-evidenced.
- [ ] Ask Codex to review and sharpen the note text after the first draft.

### Step 6: Link to broader theory canvas

- [ ] Add candidate links to the core phenomenon, category framework, axial model, response modes, and theoretical sampling questions.
- [ ] Keep these as provisional until several topic canvases have been built.
- [ ] Move stable topic-level interpretations into the broader integration canvas later.

## Broader Integration Canvas

Build this master canvas after several topic canvases exist and have refined interpretations.

Use this structure:

- Put the core phenomenon at the centre.
- Place seven high-level categories around it.
- Link topic canvases as evidence-rich submaps rather than flattening their detail into the master canvas.
- Link response modes through axial relationships, especially `conditions -> actions/interactions -> outcomes`.
- Attach negative cases as boundary tests for the emerging theory.
- Attach theoretical sampling questions as future data needs.

Suggested attachments:

- `qualitative_analysis/04_cross_case_analysis/core_phenomenon.md`
- `qualitative_analysis/04_cross_case_analysis/category_framework.md`
- `qualitative_analysis/04_cross_case_analysis/axial_model.md`
- `qualitative_analysis/04_cross_case_analysis/response_mode_matrix.md`
- `qualitative_analysis/04_cross_case_analysis/theoretical_sampling_plan.md`

Final checks before treating the master canvas as theory-building evidence:

- [ ] Each high-level category links back to at least one topic canvas.
- [ ] Each topic-level interpretation has been triangulated against comparison notes and memos.
- [ ] Negative cases are attached as boundary tests, not hidden exceptions.
- [ ] Response modes are connected through axial relationships.
- [ ] Remaining theoretical sampling questions are explicit.
