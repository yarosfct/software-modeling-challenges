## Categories

### CAT1 — Starting is gated without a worked path
**Honesty:** finding. **Voice:** student + lecturer_interp. **Primary RQ:** RQ1.
Getting stuck before the first real application unless a demo, prior contact, or worked path is available. Wave 2: ISEL capstone required models before teaching (S8M1); wait-to-start can describe the room (copiers) without describing every student (S7M1, S10M2). **Cases:** S3, S4, S8, S9 (thin), L1, L2, L3. Neg/bound: S5, S7, S10. **Evidence:** S3M1, S4M2, S8M1, L1M1, L2M1, L3M4, S7M1, S10M2. Negative: S5M3, S10M2.

### CAT2 — Notation and symbol overload create doubt
**Honesty:** finding. **Voice:** student. **Primary RQ:** RQ1.
Unfamiliar symbols, arrows, and frameworks stall start and mid-work. Lookalike families (S8M3) are a light add; S7/S10 switch pain lives on CAT14, not here. **Cases:** S1, S2, S3, S5, S8. **Evidence:** S1M1, S3M3, S2M3, S5M2, S8M3.

### CAT3 — Teacher examples and walkthroughs unlock work
**Honesty:** finding. **Voice:** student + lecturer_practice. **Primary RQ:** RQ2.
Worked examples and whiteboard walkthroughs are the main pedagogical unlock. Wave 2 instantiates (S7 board ritual; S8 examples teach notation more than the expected answer; S9M1 thin). **Cases:** S1–S9, L1, L3. **Evidence:** S1M2, S2M2, S4M2, S7M1, S8M1, L1M2, L3M4. Negative (withhold examples): L4M6.

### CAT4 — Students invent process strategies when teaching is thin
**Honesty:** finding. **Voice:** student. **Primary RQ:** RQ2.
Trial-and-error text-to-model, objects-then-relations, symbols-to-words, early drafts — plus attack-to-survive vs wait-to-copy (S7M1), pencil-to-pen before teaching (S8M1), notebook-then-board (S10M2). **Cases:** S1, S2, S3, S5, S7, S8, S10 (S9 thin). **Evidence:** S1M2, S2M2, S3M2, S5M3, S7M1, S8M1, S10M2.

### CAT5 — Feedback arrives too late
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ2 (secondary RQ3).
End-of-course or end-delivery feedback lets errors compound; lecturers stage loops that time/ECTS truncate. Wave 2 **rework dimension**: walk-around changes (S8M2), timed local rewrite (S10M3), grade-locked full redo (S7M3). Not a dedicated refine CAT. **Cases:** S1, S2, S7, S8, S10, L1, L2, L3. **Evidence:** S1M5, S2M4, S7M3, S8M2, S10M3, L1M6, L2M2, L3M5.

### CAT6 — Feedback access depends on initiative and format
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ2 (secondary RQ3).
Detailed feedback only if asked; public formats favour outgoing students; shy students need private channels. Wave 2: graded-work gating (S8M2), drawing-skill hiding (S9M2), desk walk-around vs raising a hand (S10M2). **Cases:** S2–S10, L1. **Evidence:** S2M4, S3M2, S4M3, S5M5, S6M4, S7M4, S8M2, S9M2, S10M2, L1M6.

### CAT7 — Semantic checking is valued
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ3 (secondary RQ2).
Tools/checks that catch invalid models are wanted — not “heavy tools always beat drawing.” Wave 2: checker dropped for UI (S7M2); optional Camunda/Archi unused (S8M2). **Cases:** S2–S8, L1–L4. **Evidence:** S3M4, S4M5, S5M4, S6M3, S7M2, S8M2, L1M5, L3M1, L4M5.

### CAT8 — Tool friction, switching, and cost
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ3.
Option overload, licensing, mid-course switches, slow/corrupt tools. S1 prefers simpler draw.io over StarUML. Wave 2: antique compile UI (S7M2); unused semantic suites (S8M2); archaic UML menus (S9M2). **Cases:** S1, S3, S6–S9, L1, L2, L4. **Evidence:** S1M4, S3M4, S6M3, S7M2, S8M2, S9M2, L1M5, L4M5, L2M3.

### CAT9 — Groups can kill or save the model
**Honesty:** finding. **Voice:** student. **Primary RQ:** RQ3.
Code-first pressure or passive teammates kill diagrams; ownership, pairs, live boards, stand-ups keep them alive. Wave 2: rushed teammate (S7M3); split-by-notation + peer review (S7M4, S10M5). **Not S9.** **Cases:** S1, S4, S5, S6, S7, S8, S10. **Evidence:** S1M3, S4M1, S5M1, S5M4, S6M4, S7M3, S7M4, S10M5.

### CAT10 — Real audience makes modelling worth it
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ3.
A concrete reader (supervisor, stakeholders, TA) pulls quality up; domain excitement alone is weaker. Wave 2: thesis reader vs low-stakes teacher (S7M5, S10M5). **Cases:** S2–S7, S10, L2, L4. **Evidence:** S2M5, S4M4, S5M1, S3M6, S7M5, S10M5, L2M5, L4M3.

### CAT11 — Course load and theory–practice gaps
**Honesty:** finding. **Voice:** lecturer_interp + student. **Primary RQ:** RQ3.
Heavy continuous assessment, missed theory, slide-only catch-up, late curriculum value. Wave 2 student dimension: concurrent load + low interest *despachar* (S7M6); paid job not ECTS (S8M3). **Cases:** L1–L4, S1, S3, S6, S7, S8. **Evidence:** L1M3, L2M5, L3M4, L4M1, S3M5, S1M6, S6M3, S7M6, S8M3.

### CAT12 — Hard to judge good enough
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ1.
No compile result; quality = walkthrough, justification, granularity, readability; multiple valid solutions. Wave 2: homemade list + exam faith (S7M2); explainability for defence (S10M5). **Cases:** S1, S2, S4–S7, S9 (thin), S10, L1, L2, L4. **Evidence:** S6M2, S4M2, S5M2, S1M5, S7M2, S10M5, L4M4, L2M2, L1M6.

### CAT13 — AI used as explainer, not generator
**Honesty:** finding. **Voice:** student. **Primary RQ:** RQ2.
Students use AI to explain options / compare approaches; reject generation for graded work. S10M4 is the first Portuguese lived incident. **Not S9 wish.** *Not* lecturer redesign wishes. **Cases:** S4, S5, S6, S10. **Evidence:** S4M5, S5M4, S6M5, S10M4.

### CAT14 — Cross-notation switching is hard
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ1 (secondary RQ3).
Moving across notation families loses traceability or requires a new mindset/tool set. Wave 2: S10M1 BPMN-to-UML “different questions” (same family as S6); S7M5 lighter syntax; S8M3 lookalikes. **Not S9.** **Cases:** S6, S7, S8, S10, L1, L3 (S5 adjacent). **Evidence:** S6M1, S7M5, S8M3, S10M1, L1M4, L3M7, S5M2.

## Phenomena

Short cross-cutting claims from the categories. Each is tagged `[finding]`.

### PH1 — Turning a written problem into the first diagram `[finding]`
The hard, under-taught step is making the first model from a problem text — not memorising symbol names. Fed by CAT1, CAT3, CAT4.

### PH2 — No auto-check, so the teacher is the “right/wrong” signal `[finding]`
Unlike code, a model does not compile. Students mostly learn they are wrong when a teacher (or late feedback) tells them. Fed by CAT5, CAT6, CAT12.

### PH3 — Want checks and explanations, not auto-drawn homework `[finding]`
Across tools and AI, people ask for validation and help understanding — not a machine that draws the assignment. Fed by CAT7, CAT8, CAT13.

### PH4 — A diagram survives only if someone owns it and someone reads it `[finding]`
Group ownership and a real audience decide whether modelling stays alive and careful. Fed by CAT9, CAT10.
