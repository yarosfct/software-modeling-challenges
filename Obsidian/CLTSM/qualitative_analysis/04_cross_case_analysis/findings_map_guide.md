## Categories

### CAT1 — Starting is gated without a worked path
**Honesty:** finding. **Voice:** student + lecturer_interp. **Primary RQ:** RQ1.
Getting stuck before the first real application unless a demo, prior contact, or worked path is available. **Cases:** S3, S4, L1, L2, L3. **Evidence:** S3M1, S4M2, L1M1, L2M1, L3M4. Negative: S5M3.

### CAT2 — Notation and symbol overload create doubt
**Honesty:** finding. **Voice:** student. **Primary RQ:** RQ1.
Unfamiliar symbols, arrows, and frameworks stall start and mid-work. **Cases:** S1, S2, S3, S5. **Evidence:** S1M1, S3M3, S2M3, S5M2, S1-C12.

### CAT3 — Teacher examples and walkthroughs unlock work
**Honesty:** finding. **Voice:** student + lecturer_practice. **Primary RQ:** RQ2.
Worked examples and whiteboard walkthroughs are the main pedagogical unlock. **Cases:** S1–S6, L1, L3. **Evidence:** S1M2, S2M2, S4M2, L1M2, L3M4. Negative (withhold examples): L4M6.

### CAT4 — Students invent process strategies when teaching is thin
**Honesty:** finding. **Voice:** student. **Primary RQ:** RQ2.
Trial-and-error text-to-model, objects-then-relations, symbols-to-words, early drafts. **Cases:** S1, S2, S3, S5. **Evidence:** S1M2, S2M2, S3M2, S5M3.

### CAT5 — Feedback arrives too late
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ2 (secondary RQ3).
End-of-course or end-delivery feedback lets errors compound; lecturers stage loops that time/ECTS truncate. **Cases:** S1, S2, L1, L2, L3. **Evidence:** S1M5, S2M4, L1M6, L2M2, L3M5.

### CAT6 — Feedback access depends on initiative and format
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ2 (secondary RQ3).
Detailed feedback only if asked; public formats favour outgoing students; shy students need private channels. **Cases:** S2–S6, L1. **Evidence:** S2M4, S3M2, S4M3, S5M5, S6M4, L1M6.

### CAT7 — Semantic checking is valued
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ3 (secondary RQ2).
Tools/checks that catch invalid models are wanted — not “heavy tools always beat drawing.” **Cases:** S2–S6, L1–L4. **Evidence:** S3M4, S4M5, S5M4, S6M3, L1M5, L3M1, L4M5.

### CAT8 — Tool friction, switching, and cost
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ3.
Option overload, licensing, mid-course switches, slow/corrupt tools. S1 prefers simpler draw.io over StarUML. **Cases:** S1, S3, S6, L1, L2, L4. **Evidence:** S1M4, S3M4, S6M3, L1M5, L4M5, L2M3.

### CAT9 — Groups can kill or save the model
**Honesty:** finding. **Voice:** student. **Primary RQ:** RQ3.
Code-first pressure or passive teammates kill diagrams; ownership, pairs, live boards, stand-ups keep them alive. **Cases:** S1, S4, S5, S6. **Evidence:** S1M3, S4M1, S5M1, S5M4, S6M4.

### CAT10 — Real audience makes modelling worth it
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ3.
A concrete reader (supervisor, stakeholders, TA) pulls quality up; domain excitement alone is weaker. **Cases:** S2–S6, L2, L4. **Evidence:** S2M5, S4M4, S5M1, S3M6, L2M5, L4M3.

### CAT11 — Course load and theory–practice gaps
**Honesty:** finding. **Voice:** lecturer_interp + student. **Primary RQ:** RQ3.
Heavy continuous assessment, missed theory, slide-only catch-up, late curriculum value. **Cases:** L1–L4, S1, S3, S6. **Evidence:** L1M3, L2M5, L3M4, L4M1, S3M5, S1M6, S6M3.

### CAT12 — Hard to judge good enough
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ1.
No compile result; quality = walkthrough, justification, granularity, readability; multiple valid solutions. **Cases:** S1, S2, S4–S6, L1, L2, L4. **Evidence:** S6M2, S4M2, S5M2, S1M5, L4M4, L2M2, L1M6.

### CAT13 — AI used as explainer, not generator
**Honesty:** finding. **Voice:** student. **Primary RQ:** RQ2.
Students use AI to explain options / compare approaches; reject generation for graded work. **Cases:** S4, S5, S6. **Evidence:** S4M5, S5M4, S6M5. *Not* lecturer redesign wishes.

### CAT14 — Cross-notation switching is hard
**Honesty:** finding. **Voice:** both. **Primary RQ:** RQ1 (secondary RQ3).
Moving across notation families loses traceability or requires a new mindset/tool set. **Cases:** S6, L1, L3 (S5 adjacent). **Evidence:** S6M1, L1M4, L3M7, S5M2. Translation methodology still S6-heavy.

## Phenomena

Short cross-cutting claims from the categories. Each is tagged `[finding]`.

### PH1 — Turning a written problem into the first diagram `[finding]`
The hard, under-taught step is making the first model from a problem text — not memorising symbol names. Fed by CAT1, CAT3, CAT4.

### PH2 — No auto-check, so the teacher is the “right/wrong” signal `[finding]`
Unlike code, a model does not compile. Students mostly learn they are wrong when a teacher (or late feedback) tells them. Fed by CAT5, CAT6, CAT12.

### PH3 — Want checks and explanations, not auto-drawn homework `[finding]`
Across tools and AI, people ask for validation and help understanding — not a machine that draws the assignment. Fed by CAT7, CAT8, CAT13.

### PH4 — A diagram survives only if someone owns it and someone reads it `[finding]`
Group ownership and a real audience decide whether modelling stays alive and careful. Fed by CAT9, CAT10.
