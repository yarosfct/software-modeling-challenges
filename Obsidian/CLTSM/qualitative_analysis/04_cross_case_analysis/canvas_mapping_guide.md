# Canvas Mapping Guide

## Purpose

Use canvases as clean navigation and synthesis surfaces, not as full traceability diagrams.

The detailed analysis already lives in:

- `02_first_cycle_coding`: excerpt-level evidence
- `03_memos`: memo-level interpretation
- `04_cross_case_analysis`: comparison notes, negative cases, category framework, and axial model

Canvas nodes should point toward that material and make the analytic structure easy to see.

## Main Rule

Keep analytical density inside notes. Keep the canvas visually sparse.

For each topic canvas, use this basic structure:

```text
Overview note -> Claims note -> Evidence index note -> Comparison file

Evidence index note -> selected memo files
Evidence index note -> optional negative-case files
```

This avoids crowded many-to-many connections while preserving traceability through attached files.

## Standard Topic Canvas Nodes

### Overview Note

Use one text node or Markdown note that answers:

- What is this topic?
- Why does it matter to the thesis?
- How does it connect to the core phenomenon?

### Claims Note

Use one text node or Markdown note containing 2-4 short cross-case claims.

Good claim shape:

> Worked examples support independence when they expose modelling rationale and fade assistance; final-only examples risk surface imitation.

Avoid making a large claim from only one interview. If only one case supports a point, label it as a case observation or candidate claim.

### Evidence Index Note

Use one text node or Markdown note that groups evidence by role:

- Strong support
- Qualifications or negative cases
- Useful contrasts
- Implications
- Open checks

The evidence index should name the memo IDs and briefly state why each is attached. It should not reproduce every quote.

### File Nodes

Attach the relevant cross-case comparison note, selected memo files, and any negative-case files.

Do not attach every transcript or coding sheet by default. The memo files already link the canvas to the lower evidence level. Add coding sheets or transcripts only when you need direct excerpt verification.

## Link Labels

Use very few edge labels:

- `frames`
- `claims`
- `indexes`
- `summarized in`
- `evidence`
- `qualified by`

If the canvas starts needing many labels, move that detail into the evidence index note.

## Recommended Layout

Arrange each canvas as four simple zones:

```text
[Overview] -> [Claims] -> [Evidence index] -> [Comparison file]
                         |
                         v
                  [Memo and negative-case files]
```

Keep memo files in compact vertical stacks grouped by support, qualification, and implications.

## Working Process

For each new topic canvas:

1. Create the three notes: overview, claims, evidence index.
2. Attach the comparison file.
3. Attach only the most relevant memo files.
4. Attach negative-case files only when they directly qualify the claim.
5. Draw only the standard simple edges.
6. Ask Codex to rewrite the three notes for clarity, directness, and consistency.

## Methodological Cautions

- S4-S6 are reconstructed transcripts; avoid treating their wording as verified quotation without source checking.
- Lecturer accounts of student behaviour are lecturer interpretations unless confirmed by student evidence.
- Tool-support and AI-support claims are design implications, not validated intervention effects.
- Prefer bounded, conditional claims over universal statements.
- Do not claim theoretical saturation from these canvases alone.
